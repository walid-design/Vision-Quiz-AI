Build a **native mobile application** called **VisionQuiz AI** using:

* React Native
* Expo
* TypeScript
* A backend/API that runs securely server-side
* OpenAI API integration
* Expo Camera for live camera access

This is a university senior project demonstrating real-time visual recognition and AI analysis of multiple-choice questions shown on another computer screen.

The application must be optimized for:

1. Fast response time
2. High answer accuracy
3. Reliable question-change detection
4. Minimal API calls
5. Real phone camera usage

Do NOT build this as only a desktop web application.

I need to be able to test it on my Android or iPhone using Expo Go without publishing it to an app store.

# Core User Flow

The user opens VisionQuiz AI on their phone.

The phone rear camera points toward a computer monitor displaying a multiple-choice question.

The app continuously monitors a selected region of the computer screen.

When a new question appears:

1. Detect that the visible question has changed.
2. Capture one high-quality frame of the selected question area.
3. Crop the image to the selected detection region.
4. Send the cropped image to the backend.
5. Analyze the image using a vision-capable AI model.
6. Read the question and ALL visible answer choices.
7. Determine the most appropriate answer.
8. Return a structured response.
9. Display the answer prominently on the phone.
10. Continue watching for the next question.

Do NOT repeatedly analyze the same question.

The app should automatically recognize when the computer user presses Next and a new question appears.

# IMPORTANT — Do Not Depend Only On OCR

The primary architecture should use direct image/vision understanding.

The cropped image should be sent to a vision-capable AI model that can see:

* Question text
* Answer choices
* Images or diagrams inside the question when present
* Technical terminology
* Commands
* Product names
* Certification terminology

Traditional OCR can be implemented as an optional/debugging system, but it should NOT be the only method of recognizing the question.

Create the architecture so different recognition methods can be compared later.

# AI Analysis

The mobile app sends:

* Cropped question image
* Selected subject/certification
* Session settings

The OpenAI API key must NEVER be placed in the React Native frontend.

Store it securely in:

OPENAI_API_KEY

on the server/Replit Secrets.

# FAST + VERIFIED ANSWERING ARCHITECTURE

Implement two possible stages.

## Stage 1 — Fast Analysis

Immediately analyze the captured question.

For clear questions with high confidence, return the answer immediately.

Target the fastest reasonable response.

## Stage 2 — Verification

If any of these conditions occur:

* confidence is below a configurable threshold such as 0.85
* question text is unclear
* answer options are ambiguous
* multiple answers appear plausible
* image quality is poor

then automatically perform a second verification analysis.

The second analysis should independently reconsider the entire question.

If the first and second analysis agree, mark:

verified: true

If they disagree, perform a final decision/reasoning step.

Do NOT run expensive verification for every easy question.

The goal is:

easy question → fast answer

difficult question → verify before presenting a confident answer

# QUESTION CHANGE DETECTION

This is extremely important.

Do NOT continuously upload camera frames to the server.

Perform lightweight frame comparison locally on the phone.

Suggested logic:

* periodically capture a low-resolution preview of the detection region
* compare it with the previous frame
* determine whether the screen changed significantly
* if it did not change, do nothing
* if it changed, wait briefly for the screen to stabilize
* capture a high-quality image
* analyze the new image

The system should recognize this flow:

Question 1 displayed
→ analyze once
→ keep watching
→ screen unchanged
→ no API calls
→ user presses Next on computer
→ screen changes
→ wait until new question stabilizes
→ capture
→ analyze Question 2

Add configuration values for:

Frame comparison interval
Change sensitivity
Screen stabilization delay
Confidence verification threshold

Start with sensible defaults.

# DUPLICATE QUESTION PROTECTION

Store a fingerprint/hash or normalized representation of the previous question.

If the newly detected question appears identical to the previous question, do not analyze it again.

Also prevent multiple simultaneous AI requests.

Use a state machine such as:

IDLE
WATCHING
CHANGE_DETECTED
STABILIZING
CAPTURING
ANALYZING
VERIFYING
ANSWER_READY

Make sure overlapping API calls cannot happen.
